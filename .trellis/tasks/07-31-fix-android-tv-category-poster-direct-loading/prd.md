# 全端 Flutter 分类列表封面直连加载问题排查

## Goal

先定位“电影、剧集、动漫、综艺”分类列表中，第一页或已有缓存封面正常，而后续分页的未缓存封面不加载或加载很慢的真实原因；对已经被源码确认的 Flutter 重复异步工作做最小修复。图片 URL、请求头、直连/代理选择和原生 TV 工程保持不变。

本任务覆盖 Flutter 普通分类页和 Flutter TV 分类/首页网格，以及它们共用的图片源设置、URL 解析和网络请求边界；明确不做 `re-android` TV、`kotlin-tv` 或其它原生 TV 实现。

## Confirmed Facts

- Flutter 普通分类页由 `lib/screens/movie_screen.dart`、`tv_screen.dart`、`anime_screen.dart`、`show_screen.dart` 和 `lib/widgets/douban_movies_grid.dart`/`video_card.dart` 组成。
- Flutter TV 卡片封面位于 `lib/tv_app/widgets/tv_video_card.dart`。`_TvCoverImage` 先异步解析 URL，再异步判断磁盘缓存；滚动中或卡片不在 viewport 时会延迟真实图片请求，并每 120ms 重新判断。
- Flutter 图片直连模式在 `lib/utils/image_url.dart` 中保留原始豆瓣图片 URL，同时为豆瓣图片增加 Referer、User-Agent 和 Accept 请求头；直连模式本身不会把 URL 改成代理地址。
- Flutter TV 网格使用懒构建和分页加载，后续卡片只有在进入构建/视口和延迟门控放行后才会创建真正的图片请求。因此“后续数据已到但图片尚未请求”与“图片请求已发出但网络/解码慢”需要分开判断。
- 普通 Flutter 分类页和 TV 分类页使用不同的列表/卡片组件，不能仅凭 TV 卡片的视口门控推断普通端也有相同问题。
- 当前没有足够运行时证据证明是分页数据、图片 URL、反盗链、DNS/连接、Flutter 图片门控或解码资源中的哪一层。

## Requirements

- 只分析 Flutter 普通端和 Flutter TV；允许修改 Flutter 图片配置/缓存调用的共享代码，不修改 Android 宿主或任何原生 TV 工程。
- 先确认实际测试 APK、启动入口、四个 Tab 的页面/列表/图片组件路径和版本。
- 对“第一页/缓存/后续未缓存”建立可重复对照，记录分页编号、卡片索引、标题、原始 URL、最终 URL、请求是否发出、缓存命中、HTTP 状态、首字节/解码耗时、失败类型和卡片是否处于可视区。
- 区分以下阶段：数据分页返回、卡片进入组合、图片请求放行、网络响应、图片解码、图片绘制/回收。不能把骨架图持续显示直接归因于网络慢。
- 对普通 Flutter 分类页和 Flutter TV 逐条梳理 URL 替换、请求头、缓存 key、懒加载/视口门控、分页触发及失败回退。
- 最终输出带证据等级的根因排序、需要补充的运行时证据、建议的后续 Flutter 修复任务边界；若普通端和 TV 根因不同，必须拆开记录。

## Acceptance Criteria

- [x] 任务文档明确记录实际测试 APK 属于 Flutter 哪条页面实现，并列出四个 Tab 的页面/列表/图片组件链路。
- [ ] 完成至少一次“首屏未缓存、后续页未缓存、已有缓存、分页未触发/已触发”的对照记录，不能只凭主观加载速度下结论。
- [x] 静态链路已区分数据、组合、请求门控、响应、解码和绘制阶段；运行时网络/解码证据仍受设备缺失限制。
- [ ] 直连模式的最终 URL、请求头和实际网络目标经过核对；反盗链、HTTP 状态、超时、DNS、连接复用和图片尺寸/解码压力有单独结论。
- [x] Flutter 普通端与 Flutter TV 的差异、共同问题和不确定项分别列出，并给出高/中/低置信度。
- [x] 已确认的重复配置/缓存读取问题有对应回归测试和最小 Flutter 修复。
- [x] 本轮没有修改图片 URL、请求头、直连/代理选择、分页接口或原生 TV 工程。

## Out of Scope

- 不分析或修复 `re-android` TV、`kotlin-tv` 或其它原生 TV 图片链路。
- 不做图片网络协议、预取、解码兜底或直连/代理策略改造；允许修复重复读取配置和重复创建缓存策略服务造成的等待。
- 不修改分页接口、图片 URL、请求头、Coil ImageLoader 或 Flutter 图片组件。
- 不把“切换到代理源后看起来变快”当作本轮修复；代理源只能作为诊断对照条件。
- 不处理 PIP、播放器、焦点导航或分类页视觉改版。

## Analysis Gate

用户已确认开始排查，并进一步授权在发现确认问题后直接修改代码。当前实现边界限定为已由源码确认的 Flutter 配置/缓存重复工作；直连网络的 HTTP、DNS、反盗链和解码问题因缺少设备证据仍只记录分析，不在本任务中猜测修复。
