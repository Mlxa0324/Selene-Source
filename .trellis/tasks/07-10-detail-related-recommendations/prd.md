# 修复详情页相关推荐列表

## Goal

修复 Kotlin TV 详情页底部相关推荐始终不显示的问题，复用 Flutter TV/手机端的豆瓣详情推荐数据链路，并让推荐作为独立次要任务运行，不阻塞首播和后台补源。

## Confirmed Facts

- `TvDetailRoute` 已具备推荐横向列表；当 `recommendCards` 为空时整段隐藏。
- `TvDetailViewModel` 已注入 `loadRecommends`，但当前必须等待精确源、标题补源和收藏加载全部完成后才发起推荐请求。
- 标题补源使用 SSE/批量回退，耗时长或未结束时会使推荐一直无法启动。
- 当前推荐异常通过 `runCatching(...).getOrDefault(emptyList())` 静默降级，缺少失败原因和阶段状态。
- `TvAppContainer` 已存在豆瓣 ID 解析与豆瓣详情 HTML 推荐抓取的未提交接线，但解析器和网络链路缺少回归测试。
- Flutter TV 在预览真实起播后延迟 2 秒启动推荐；没有可播源时可强制启动。Flutter 手机端也通过豆瓣详情的 `recommends` 渲染列表。

## Requirements

- 推荐加载必须从精确源/标题补源主协程中拆出，不能等待完整补源结束。
- 有可播预览时，对齐 Flutter TV：首个播放请求成功下发并开始播放后延迟约 2 秒加载推荐。
- 无可播源但入口或详情具备豆瓣身份时，在主加载收敛后仍尝试加载推荐。
- 豆瓣 ID 优先使用详情字段，其次使用豆瓣入口 ID，再使用现有标题与年份匹配逻辑解析。
- 推荐 HTML 抓取和解析需要可测试；解析出的 ID、标题、海报和评分转换为 `TvVideoCard`。
- 推荐加载失败不得清除已发现的播放源，也不得改变首播、空态或收藏状态。
- 对请求失败、豆瓣 ID 缺失、HTML 解析为空和成功数量输出简洁诊断日志，不记录大段响应正文。
- 旧页面的过期推荐回包不得覆盖新详情页状态。

## Acceptance Criteria

- [x] 后台标题补源长时间未完成时，首播后的推荐任务仍能独立启动并回写列表。
- [x] 注入推荐加载器返回非空卡片时，`recommendCards` 更新且推荐区展示。
- [x] 无可播源但具备豆瓣 ID 时，主加载结束后仍会尝试推荐加载。
- [x] 推荐加载器抛出异常时，播放状态、线路列表和空态保持不变。
- [x] 切换详情后，旧请求回包不会覆盖当前推荐列表。
- [x] 豆瓣 HTML 解析器覆盖正常推荐、缺少评分、无推荐区和非法内容场景。
- [x] App 容器测试覆盖豆瓣 ID 优先级与推荐加载器接线。

## Out of Scope

- 不新增非豆瓣推荐源。
- 不重做推荐卡片视觉样式和详情页整体布局。
- 不扩展推荐卡片点击后的新导航能力，沿用当前交互范围。
