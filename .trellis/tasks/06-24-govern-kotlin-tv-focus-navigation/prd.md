# 治理 Kotlin TV 全局遥控焦点移动

## Goal

系统治理 Kotlin TV 端遥控器上下左右焦点移动不稳定的问题，让首页、详情页、搜索页、历史/收藏/设置/直播等页面的焦点路径可预测、可测试、可持续维护。

## Background

- 用户反馈 Kotlin TV 端“上下左右焦点，移动很是问题”。
- 已完成过一次首页 Tab 下移修复：`TvPosterRail` 记录最近真实获焦卡片，让顶部导航下探回到真实内容卡片。
- 当前焦点逻辑分散在 `app-tv` 顶部导航、`core-design` 卡片/列表组件、各 `feature-tv-*` 页面和全屏播放器菜单中，容易出现某个页面单独补丁修好、另一个页面回归的情况。
- 本任务不是单点修一个按钮，而是先建立全局焦点契约，再分页面补齐路径。

## Scope

- Android Kotlin TV 代码：`re-android/app-tv`、`re-android/core-design`、`re-android/feature-tv-*`。
- TV 遥控器方向键：上、下、左、右、确认、返回。
- 首屏入口焦点、顶部导航回流、横向列表边界、纵向页面滚动、详情页播放器/线路/选集、搜索键盘与结果区、设置表单与功能入口、播放页菜单。

## Out Of Scope

- Flutter TV 焦点逻辑重写。
- 移动端触摸/鼠标交互改造。
- 播放源、播放器内核、详情数据加载逻辑的业务重写。
- 大规模视觉样式重做；本任务只做焦点需要的最小 UI 状态辅助。

## Requirements

- 顶部导航按下方向键必须进入当前页面的稳定内容入口；内容入口不能绑定到已经离开组合树的 Lazy 列表节点。
- 从内容区按上方向键必须回到符合当前上下文的顶部或上一区域，而不是丢焦或跳到不可见区域。
- 横向列表左右移动到边界时必须稳定停在当前边界项，不允许焦点逃逸到无关区域。
- 横向列表从顶部或其它区域进入时，应优先回到最近真实获焦项；首次进入时回到首个可用项。
- 纵向页面中焦点移动到新分区时，页面必须滚动到可见且稳定的位置。
- 详情页焦点图必须覆盖播放器、全屏/收藏/反馈、线路、选集、选集分组、推荐和底部操作之间的上下左右路径。
- 搜索页焦点必须覆盖键盘、清空/搜索/删除按钮、热词/历史、结果区之间的进出路径。
- 历史、收藏、直播和设置页必须接收 `contentFocusRequester`，并在空态、加载态、列表态都有真实 focusable 目标。
- 全屏播放器菜单必须覆盖主菜单和二级菜单之间的上下移动，返回和方向键不能抢焦点。
- 所有新增焦点逻辑必须有契约测试或纯逻辑单测；无法做 Compose 集成测试的路径使用源码契约测试锁定关键结构。
- 不新增隐藏可聚焦桥接节点，除非没有其它真实节点可用；如必须使用，需要在设计文档说明原因和边界。

## Acceptance Criteria

- [ ] 形成一份 Kotlin TV 全局焦点地图，列出每个页面的入口、退出、上下左右路径和边界行为。
- [ ] 首页 Tab、分类页、历史页、收藏页、直播页从顶部导航下探内容区稳定可用。
- [ ] 首页和列表页横向 rail 在靠右项上移到顶部后，再下移能回到最近真实获焦项。
- [ ] 详情页从播放器、操作按钮、线路、选集、选集分组、推荐区上下左右移动不丢焦。
- [ ] 搜索页键盘到右侧面板、右侧面板回键盘、结果区和操作按钮之间移动稳定。
- [ ] 设置页表单项上下移动稳定，顶部导航下探能落到第一个可编辑/可点击控件。
- [ ] 全屏播放器底部菜单主/次级选项上下移动稳定，左右键 seek 不影响菜单焦点契约。
- [ ] 新增或更新对应单元/契约测试，并通过相关 `testDebugUnitTest`。
- [ ] `git diff --check` 通过。

## Risks

- 当前工作区已有大量未提交改动，实施时必须只改焦点相关文件，不能顺手整理其它播放/数据逻辑。
- 焦点修复容易被视觉布局、Lazy 列表组合时机和 `FocusRequester` 绑定顺序影响，必须先写失败测试或契约断言。
- 多页面一次性修改风险较高，实施应按“共用组件 -> 首页/列表 -> 详情 -> 搜索/设置/播放页”的顺序分阶段验证。
