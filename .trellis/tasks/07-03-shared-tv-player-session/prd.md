# 详情页与全屏共享播放器会话重构

## Goal

在保持 TV 详情页和 TV 全屏播放器继续分开维护的前提下，把两者的播放器会话收敛为同一条共享链路，让“详情页预览 -> 全屏播放”切换尽量无感，避免出现明显的播放器重建卡顿、重新缓冲和状态丢失。

## Confirmed Facts

- 当前 `TvNavGraph` 会在详情页和全屏页分别创建独立的播放器对象：
  - 详情页使用 `detailPlayerSession` / `detailExoEngine`
  - 全屏页使用 `webViewPlayerSession` / `exoPlayerEngine`
- 详情页点击“全屏播放”时，当前实现会先把 `PlaybackRequest` 存进 `TvPlaybackRequestStore`，再导航到全屏页。
- 详情页预览和全屏页都会各自调用一次 `engine.load(request)`，同一剧集从预览切到全屏时仍然存在重复加载风险。
- `WebViewPlayerSurface` 当前每次组合都会新建 `WebView`，播放地址不变时也无法天然复用已有页面实例。
- `ExoPlayerSurface` 已支持把同一个 `ExoPlayer` 绑定到不同 `PlayerView`，但当前导航层没有共享同一个 `ExoPlayerEngine`。
- 当前播放器资源缺少统一释放宿主；除 `TvPlayerEngineSwitcher` 外，详情页和全屏页主链路没有统一的 `release` 管理。
- 用户已明确确认：
  - 详情页和全屏页继续分开，不合并成一个文件。
  - 目标是详情页切全屏时尽量没有“播放器卡一下、像重新开了一个播放器”的感觉。

## Requirements

- 详情页和全屏页继续保持独立页面和独立文件边界，不把两页 UI 暴力合并。
- 详情页预览播放器和全屏播放器必须共享同一份播放器会话，而不是只共享播放请求对象。
- 当当前播放内容身份未变化时，详情页进入全屏不得再次触发破坏性重载。
- 共享会话需要覆盖两种内核：
  - `exo` 走同一 `ExoPlayerEngine`
  - `webview` 走同一 `WebView` 会话，避免重新创建页面导致明显重载感
- 共享链路需要把当前播放请求、线路列表、剧集列表统一收敛，避免导航层和播放器层各存一份状态。
- 播放器资源释放要有明确时机：
  - 详情页 -> 全屏页
  - 全屏页 -> 弹幕匹配页
  - 全屏页 -> 返回详情页
  这些同一播放流内部跳转不能提前释放
- 离开整个详情/播放器播放流后，必须能统一释放播放器资源，避免状态串扰和资源泄漏。

## Acceptance Criteria

- [ ] `TvNavGraph` 顶层新增共享播放器宿主，详情页和全屏页都从同一宿主读取播放会话。
- [ ] 详情页进入全屏时，不再为同一播放流重新创建第二套 `PlayerEngine` / `WebView` 播放会话。
- [ ] 当媒体身份相同（同视频、同线路、同剧集、同 URL）时，详情页预览进入全屏不会再次执行一次破坏性 `engine.load(...)`。
- [ ] `webview` 内核可以复用同一 `WebView` 播放实例，切全屏时不重新加载同一个播放页。
- [ ] 退出全屏回详情时，共享播放器会话仍可被详情页继续接管，不因路由切换被提前释放。
- [ ] 离开详情/播放器播放流后，共享播放器宿主会统一释放会话和内核资源。
- [ ] 新增或更新的单测/契约测试覆盖共享宿主、无重复加载、会话释放边界和 WebView 复用契约。

## Out Of Scope

- 把详情页和全屏页合并成单个页面文件。
- 重做详情页视觉布局、全屏菜单交互或弹幕产品逻辑。
- 改动播放器内核选型策略（本轮不调整 Exo / WebView 偏好与自动降级规则）。
