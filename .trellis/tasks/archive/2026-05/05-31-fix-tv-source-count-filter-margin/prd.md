# 修复 Flutter TV 继续观看源集数刷新和分类弹层边距

## Goal

修复 Flutter TV 端从继续观看进入详情页时，播放源集数标签偶发停留在 `电影天堂(0)` 的问题；同时优化电影/剧集/动漫/综艺顶部分类筛选弹层的顶部留白，避免确认键打开后贴近屏幕顶边。

## What I already know

- TV 详情页会先用继续观看记录中的源信息进入页面，再通过接口加载真实播放源详情。
- 用户反馈接口已经请求到数据，但播放源标签仍显示 `电影天堂(0)`，退出重进才更新，说明前端某处源列表/当前源缓存没有被真实结果替换或刷新。
- TV 电影、剧集、动漫、综艺页通过顶部分类筛选面板承载确认键弹出的筛选 UI。

## Assumptions

- `电影天堂(0)` 指详情页播放线路列表里源名旁的集数统计，统计应随真实 `SearchResult.episodes.length` 更新。
- 如果同一播放源后续返回了同 source/id 但 episodes 非空的新结果，应替换旧的空 episodes 结果，而不是因为去重跳过。
- 顶部分类筛选面板只需要增加 10px 顶部留白，不改变筛选项布局和焦点规则。

## Requirements

- 从继续观看进入详情页时，播放源列表里已存在的空集数源，在后续接口返回同源非空集数后必须刷新显示。
- 当前播放源 `_currentDetail` 也必须同步到最新非空 episodes，避免播放器和源标签继续使用旧空数据。
- 播放源去重逻辑不得因为 source/id 相同而忽略更完整的新数据。
- 电影、剧集、动漫、综艺顶部分类筛选弹层顶部增加 10px padding/margin。
- 补充 TV widget 回归测试覆盖源集数刷新和分类筛选顶部留白。

## Acceptance Criteria

- [x] 继续观看进入详情页后，初始空源显示 `电影天堂(0)` 时，后续同源非空结果到达后可自动更新为真实集数。
- [x] 当前播放源同步替换为非空 episodes 后，详情页可正常起播。
- [x] 源列表去重仍保留已有排序/当前源置顶规则。
- [x] 电影/剧集/动漫/综艺分类筛选弹层顶部增加 10px 留白。
- [x] 相关 TV 测试、分析和 `git diff --check` 通过。

## Notes

- 不改动后端接口。
- 不调整普通端筛选弹层。
