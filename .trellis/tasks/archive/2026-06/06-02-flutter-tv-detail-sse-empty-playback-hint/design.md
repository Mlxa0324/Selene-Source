# Flutter TV 详情页 SSE 无播放信息提示 - 技术设计

## Overview

本任务包含两个耦合点：

1. 详情页在 SSE/增量补源最终结束后仍无可播放线路时，需要展示图标空状态。
2. 搜索页进入详情页时，需要让详情页复用搜索页已经发起的同一轮 SSE 搜索；如果该搜索仍在进行中，详情页要继续接收该轮搜索的后续增量结果和最终完整结果，而不是只拿进入瞬间的快照。

第二点是第一点的前置条件。否则详情页可能因为只拿到搜索页当时的部分 `prefetchedSources`，过早判断“无可播放线路”，导致空状态错误出现。

## Current Behavior

### 搜索页

- 搜索页通过 `SearchService.searchSync` 发起 SSE/增量搜索。
- 每次增量结果会写入 `_searchResults`，最终完成后 `_isSearchResultLoading = false`。
- 打开详情页时，搜索页只把当前 `_searchResults` 里同标题的结果快照筛成 `prefetchedSources` 传给详情页。

### 详情页

- 详情页支持 `prefetchedSources`。
- 只要 `prefetchedSources` 非空，详情页就会跳过自己的 `loadMoreSources` 标题补源。
- 详情页当前没有“共享中的搜索会话”概念，因此无法继续接收搜索页后续 SSE 增量。
- 详情页空源态目前只是一行 `_buildEmptyText('暂无可用源')`。

## Root Cause

`prefetchedSources` 当前只是一次性快照，不是可持续更新的搜索会话。

结果是：

- 如果搜索页已经搜完，详情页复用快照没有问题。
- 如果搜索页还没搜完，详情页会错误地把“当前快照”当成“最终结果”来使用。
- 一旦快照非空，详情页又会跳过自己的 `loadMoreSources`，因此后续增量永远不会补进来。

## Proposed Design

### 1. 引入可共享的搜索会话对象

新增一个面向搜索页和详情页共享的轻量对象，例如：

- 当前已拿到的原始 `SearchResult` 列表
- 当前搜索是否已完成
- 增量更新通知
- 最终完成通知

这个对象由搜索页在一次 `_performSearch` 开始时创建并持有，增量结果和最终结果都持续写入它。

详情页打开时不只接收静态 `prefetchedSources`，还接收这个共享对象。

### 2. 详情页优先复用共享会话

详情页初始化补源时遵循以下优先级：

1. 先合并共享会话里当前已经拿到的同标题结果。
2. 如果共享会话还未结束，订阅其后续更新，持续把增量结果并入详情页。
3. 共享会话结束后，才把“补源流程完成”标记置真。
4. 只有在没有共享会话时，详情页才走自己原本的 `loadMoreSources` 标题补源。

这样可以保证：

- 搜索页与详情页只请求一次 SSE。
- 详情页可以完整吃到这次 SSE 的最终结果。
- 空状态只在“共享会话或本地补源真正结束后仍无源”时出现。

### 3. 空状态显式区分“完成但无结果”

详情页 `切换线路` 分区需要在以下条件同时满足时显示图标空状态：

- `_sources` 为空
- 首源加载已完成
- 补源流程已完成
- 当前不是单纯加载中

空状态结构：

- 一个语义明确的图标
- 一条主提示文案，表达“没有查到播放信息”

普通文本 `_buildEmptyText('暂无可用源')` 保留给其它不在本任务范围内的场景时可复用，或由新空态 builder 内部局部复用。

## State / Contract Changes

### 搜索页新增

- 当前搜索共享会话字段
- 在新一轮搜索开始时重建会话
- 在搜索取消、回退或新请求覆盖旧请求时，让旧会话停止继续向外派发

### 详情页新增

- 可选的共享搜索会话入参
- 订阅/取消订阅该会话的生命周期处理
- 用于判断“共享补源是否完成”的状态

## Compatibility

- 已经搜完再进详情页：行为与现在一致，只是数据来源从静态快照升级为“已完成的共享会话快照”。
- 搜索页不进入详情页：搜索页行为不变。
- 非搜索页入口进入详情页：继续走原有 `loadInitialSources + loadMoreSources`。
- `prefetchedSources` 现有能力可以保留，但它应退化为共享会话的即时快照字段，而不是唯一的跨页复用方式。

## Risks

### 风险 1：详情页重复合并同一批增量结果

共享会话可能多次推送“到当前为止的全量结果”。详情页必须继续依赖现有 `_addUniqueSources` 去重，不要按“每次推送都是新增”假设写逻辑。

### 风险 2：搜索页离开后旧会话串入新详情页

搜索页已有 `_searchRequestVersion`。共享会话也需要绑定到同一轮请求版本，旧请求失效后不能再把回包派发给新详情页。

### 风险 3：空状态过早出现

“无播放信息”只能在补源完成后显示，不能在 SSE 还在跑、但暂时还没出结果的时刻提前展示。

## Validation Strategy

重点验证以下路径：

1. 搜索页共享会话已完成后进入详情页：详情页不再发第二次 `loadMoreSources`。
2. 搜索页共享会话进行中进入详情页：详情页能继续收到后续增量和最终完整结果。
3. 共享会话最终为空：详情页出现图标空状态。
4. 共享会话最终非空：详情页不出现空状态。
