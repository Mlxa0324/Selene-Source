# 修复 Kotlin TV 首页配置后无数据

## Goal

修复 Kotlin 原生 TV 端在设置页录入后台 URL、用户名和密码后，首页仍加载失败或无数据展示的问题。

## Requirements

- 分析 Kotlin TV 端配置保存、配置读取、登录、首页数据加载和兜底分类数据加载链路。
- 优先定位截图中 `Failed to connect to /192.168.31.28:9000` 的真实来源，区分 URL 规范化问题、模拟器网络访问问题、明文 HTTP 限制、认证失败和数据接口解析失败。
- 如果用户在设置页录入的是局域网地址或缺少协议的地址，Kotlin TV 端应能规范化并稳定用于后续请求。
- 首页加载失败时的错误信息应尽量暴露可操作原因，避免只显示底层 OkHttp 文案导致无法判断配置问题。
- 修复应覆盖自动化测试，避免后续配置读取和首页数据链路回归。
- 不修改 Flutter TV 端已有行为，不提交本地配置脏改。

## Acceptance Criteria

- [x] 已创建独立 Trellis 任务并记录本问题范围。
- [x] 已定位 Kotlin TV 首页无数据的根因。
- [x] 配置后 Kotlin TV 首页能通过有效后台地址加载首页分区或兜底分类数据。
- [x] URL 规范化、配置读取或首页仓库相关改动有回归测试。
- [x] 相关 Kotlin 单测和 `app-tv` 构建通过。

## Notes

- 截图现象：设置已录入后，首页展示「首页加载失败」，错误为 `Failed to connect to /192.168.31.28:9000`。
- 当前用户希望直接分析并修复，中途不做非必要确认。
- 本次定位：APK 已读取 `http://ivy3004.s.odn.cc`，但 OkHttp 实际失败目标为 `192.168.31.28:9000`，说明当前域名/穿透/重定向未指向模拟器可访问的 Selene 后台 API，并非旧 APK 或配置未读取。
- 运行态验证：重新构建并安装 `app-tv-debug.apk` 后，首页错误文案已展示配置域名、实际失败目标和排查方向；当前 live 后台仍需修正穿透目标后才能真实加载远端数据。
