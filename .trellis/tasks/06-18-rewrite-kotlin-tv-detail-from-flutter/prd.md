# 重做 Kotlin TV 详情页对齐 Flutter TV

## Goal

推翻当前 Kotlin TV 详情页“补丁叠加式”实现，按 Flutter TV 端详情页的数据加载、首播、续播、换源、选集、焦点和空态契约重建 Kotlin 原生 TV 详情页。

目标不是只修某个空数据或焦点点位，而是把详情页主链路改成可长期维护的状态机和组件拆分：进入详情页后尽快命中可播源、立即起播、后台补源、稳定续播、遥控器焦点可预测，页面视觉和交互尽量 1:1 靠近 Flutter TV。

## Confirmed Facts

- Flutter TV 详情页入口是完整 `VideoInfo`，生产加载拆成首屏精确源、后台标题补源、推荐延迟加载三段；旧 `loadDetail` 聚合入口只保留给测试兼容。
- Flutter TV 详情页的首播门闩只允许“首个可播源命中 + 首次 `updateDataSource(startAt)`”留在关键路径；收藏、去广告、代理预热、推荐、播放器内核偏好都不阻塞首播。
- Flutter TV 支持搜索页预取源和共享搜索会话复用：搜索页已有同片名候选源或 SSE 会话时，详情页不重复发起标题补源，并继续订阅未完成的增量结果。
- Flutter TV 继续观看入口会重新读取最新播放记录，锁定 `source + id` 续播目标；源到达后必须先匹配续播目标，搜索全部完成仍未命中时才回退最佳源。
- Flutter TV 详情页焦点有明确链路：顶部搜索、播放器、全屏/收藏、线路、选集、分组、推荐、底部操作之间显式上下/左右目标，不依赖默认几何焦点猜测。
- Flutter TV 详情页横向线路和选集列表都有首尾安全留白、边界抖动、当前项可见性滚动、焦点中心超过视口 50% 才平滑滚动。
- Flutter TV 内嵌播放器无播放 URL 时不提前拉起重型播放器；有可播源后才进入播放 loading，loading 只能由真实播放进度前进来收起，不能只看 ready/play/isLoading=false。
- Kotlin 当前 `TvDetailViewModel` 仍是单次 `loadInitialDetail` + `loadMoreSources` 的薄状态，缺少并行/增量首播状态、退出打断、防重复回包、续播源锁定、保存/清理播放记录等核心状态。
- Kotlin 当前 `TvDetailRoute` 把顶部、Hero、播放器、线路、选集、推荐、底部操作集中在一个文件里，焦点主要依赖局部 `focusable/onPreviewKeyEvent`，缺少 Flutter 同款显式焦点图。
- Kotlin 当前 `TvAppContainer.createDetailViewModel()` 已有精确源失败后的标题补源兜底，但它只是前置修复，不等于完成详情页 1:1 重做。
- 原生播放器已有 `PlayerEngine`、`PlaybackRequest`、`PlaybackSnapshot`、`WebViewPlayerSession`、`WebViewPlayerEngine`，可以作为详情页共享预览/全屏状态机基础。
- `.trellis/spec/frontend/tv-mode.md` 已记录 Kotlin 原生 TV 详情页契约，包含详情加载、续播源匹配、返回高优先级打断、预览 loading、全屏复用和焦点要求。

## Requirements

- 详情页生产加载必须重建为 Flutter TV 同款三段式状态机：
  - 精确源详情和标题补源可并行或等价并发启动。
  - 任一来源先命中可播源后立即设置当前源、结束整页首屏 loading、生成预览播放请求。
  - 后续补源结果继续按 `source + id` 去重追加，同源同 ID 保留剧集更完整结果。
  - 精确源失败不阻塞标题补源；标题补源失败不影响已有精确源播放。
- 详情页必须保留并扩展可测试注入边界：
  - 初始源加载、后台补源、推荐加载、收藏读写、续播记录读写、播放器引擎都能在单元测试中注入。
  - `feature-tv-detail` 继续保持状态和回调驱动，不直接依赖 `NavController` 或 BuildConfig。
- 继续观看必须对齐 Flutter TV：
  - 进入详情页后重新读取最新播放记录，优先按 `source + id` 锁定续播目标。
  - 无续播目标时首个可播源立即起播。
  - 有续播目标时，非目标源先不自动起播；精确源和标题补源全部结束仍未命中时，回退最佳可用源。
  - 首播 `PlaybackRequest.startPositionMs` 使用最新续播秒数；播放器真实进度未到续播点时需要限次补偿 seek。
- 内嵌播放器必须对齐 Flutter TV：
  - 无播放 URL 时只展示轻量封面/占位，不提前初始化重型 WebView。
  - 有播放请求后显示 `tv-detail-preview-loading` 同款单圈 loading 和网速文案。
  - loading 只能在播放进度从本轮 loading 锚点向前推进后收起。
  - 详情预览和全屏播放器应复用同一播放会话或快照，避免进入全屏重新起播或黑屏。
- 页面 UI 必须重写为可维护组件：
  - 顶部栏：`IvyTV`、说明文案、搜索按钮、当前时间。
  - Hero：左侧 16:9 预览播放器，右侧标题、年份/来源/集数、简介、全屏和收藏按钮。
  - 线路：单行横向列表，线路展示为 `线路名（集数）`，按集数倒序，当前线路首次固定在前，用户主动换源后恢复排序。
  - 选集：单行横向选集在上，分组标签在下；20 集一组；跨组左右键无缝切换。
  - 推荐：播放开始后延迟加载；无推荐不渲染推荐区和底部多余空白。
  - 空态：搜索完成仍无播放线路时展示“搜索已完成，未找到可播放信息”；无选集展示“暂无选集”。
- 焦点必须建立显式焦点图：
  - 搜索、播放器、全屏/收藏、线路、选集、分组、推荐、底部操作都有明确上下/左右目标。
  - 横向列表首尾只做边界反馈，不跳到其它列表。
  - 上下列表移动按当前焦点水平位置选择最近可见项，不优先恢复历史停留项。
  - 详情页纵向内容获焦时自动平滑滚动到稳定位置。
- 返回和退出必须高优先级打断：
  - 详情页返回先设置退出标志、暂停播放器、后台保存进度，再立即 `popBackStack`/关闭 overlay，不等待 IO。
  - 退出后所有异步回包、播放器事件、post-frame/focus 请求必须早停。
- 播放记录和收藏：
  - 播放进度上报按 Flutter/手机端节流：小于 1 秒不保存，10 秒内重复进度不重复保存。
  - 换源先保存新源记录，保存成功后再清理旧源记录。
  - 收藏按钮读写真实收藏状态；写入失败要回滚或展示错误，不做静默假成功。
- 保持现有路由兼容：
  - 继续支持 `source::id::title` 详情 key。
  - 如果后续需要 `searchTitle/poster/year` 等更完整入口信息，应通过兼容的新 route payload 增量扩展，不破坏旧入口。

## Acceptance Criteria

- [ ] `TvDetailViewModel` 或新详情状态机测试覆盖：精确源和标题补源并发/增量返回时，首个可播源立即进入可播放状态。
- [ ] 测试覆盖：精确源失败后标题补源继续；标题补源失败但已有精确源时保持播放。
- [ ] 测试覆盖：搜索全部完成无源时展示完成空态，不一直 loading。
- [ ] 测试覆盖：续播目标命中后起播；搜索完成未命中后回退；无续播记录时立即起播。
- [ ] 测试覆盖：后台补源同 `source + id` 去重并用更完整剧集覆盖。
- [ ] 测试覆盖：切换线路保留当前集数和播放秒数，并重新生成播放请求。
- [ ] 测试覆盖：选集分组、跨组左右移动、选集/分组只在确认时切换当前分组。
- [ ] 测试覆盖：返回键先退出 UI，不阻塞保存；退出后异步回调不再改状态。
- [ ] Compose UI 测试或可执行单元测试覆盖：线路为空完成态、选集为空态、推荐为空不渲染底部操作。
- [ ] 关键文件通过 `:feature-tv-detail:testDebugUnitTest`、`:core-data:testDebugUnitTest`、`:app-tv:testDebugUnitTest`。
- [ ] 对当前改动文件执行 `git diff --check`。

## Out Of Scope

- 不重做全屏播放器底部菜单全部能力，除非它阻塞详情页预览/全屏共享链路。
- 不重做首页、搜索页、历史、收藏、设置等非详情页面。
- 不引入新的远端接口；先复用现有 `SeleneTvApi`、`TvDetailRepository`、`TvPlaybackRepository`、`TvFavoritesRepository` 能力。
- 不承诺完全像素级还原 Flutter UI，但布局、交互、焦点、加载和播放语义要对齐。
