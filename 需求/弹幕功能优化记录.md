# 弹幕功能开发与性能优化技术报告

## 1. 需求背景
本项目需要一套完整、高性能且美观的弹幕系统。主要改进点包括：UI 界面重构、修复全屏显示异常、新增手动匹配功能，以及解决在高频率弹幕下的手机发热与耗电问题。

---

## 2. 核心问题分析与解决方案

### 2.1 UI 界面 1:1 还原
*   **问题**：原有的设置面板风格不统一，缺乏精细控制（如行间距、缩放、粗细）。
*   **方案**：
    *   采用 `Colors.black.withOpacity(0.85)` 实现深色半透明毛玻璃质感。
    *   重写 Slider 样式，使其更符合现代播放器的视觉规范。
    *   将原本模糊的图标按钮替换为直观的中文屏蔽按钮（滚动、顶部、底部、彩色）。
    *   **扩展参数**：增加了 `scale` (缩放), `lineSpacing` (行间距最大 4px), `fontWeight` (粗细), `displayArea` (显示区域) 等模型字段。

### 2.2 修复全屏（横屏）弹幕消失
*   **问题根源**：移动端进入全屏时，`media_kit_video` 会创建一个新的 Overlay 或全屏路由。原本弹幕层定义在页面的 `Stack` 中，它属于竖屏页面的 UI 树，进入全屏后由于层级被覆盖导致不可见。
*   **解决方案**：
    *   **依赖注入**：在 `VideoPlayerWidget` 中增加 `danmakuLayer` 参数。
    *   **层级重构**：将弹幕层直接注入到播放器内部，渲染在视频层之上、控制层（Controls）之下。这样无论是否全屏，弹幕始终跟随播放器组件存在。

### 2.3 手动匹配功能实现
*   **逻辑**：
    *   集成 `api/v2/search/episodes` 接口，支持通过作品名模糊搜索。
    *   在全屏控制栏（`MobilePlayerControls`）增加搜索图标。
    *   通过 `DanmakuMatchPanel` 提供二级列表（动画 -> 剧集）选择。
    *   选择剧集后，通过 `episodeId` 直接重载弹幕数据流。

## 3. 性能优化（解决发烫与费电）

这是本次优化的重点，通过以下三个层面的手段降低了硬件负载：

### 3.1 渲染隔离 (RepaintBoundary)
*   **原理**：弹幕是每一帧都在移动的（高频率绘制），而视频控件或视频底图的更新频率相对较低。
*   **做法**：在 `VideoPlayerWidget` 中用 `RepaintBoundary` 包裹弹幕层。
*   **结果**：这会为弹幕层创建一个独立的 Canvas 缓存层。弹幕的移动只会在其自身的 Layer 上重绘，**不会触发整个播放器 UI（进度条、标题、返回键等）的重绘**，极大降低了 GPU 负担。

### 3.2 逻辑节流 (Throttling)
*   **原理**：播放器的进度回调 `onPositionChanged` 触发频率极高（每秒约 30-60 次）。如果每次触发都去遍历几千条弹幕列表来判断该发哪条，会产生大量无效的 CPU 计算。
*   **做法**：引入时间戳对比逻辑，将弹幕匹配检查频率限制在 **150ms 一次**。
*   **结果**：在不影响视觉连贯性的前提下，将 CPU 逻辑处理开销降低了 80% 以上。

### 3.3 属性同步优化
*   **同步视频速度**：实现 `syncVideoSpeed` 功能。
    *   公式：`当前弹幕持续时间 = 基础持续时间 / 视频播放倍速`。
    *   解决了视频加速播放时，弹幕看起来“慢半拍”的视觉违和感。

### 3.4 主题动态适配 (新增)
*   **需求**：弹幕面板（设置与匹配）需跟随系统深色/浅色模式切换。
*   **做法**：
    *   将硬编码的 `Colors.black` 替换为基于 `ThemeData.brightness` 的动态计算颜色。
    *   深色模式：保持 85%~90% 不透明度的黑色背景。
    *   浅色模式：切换为 95%~98% 不透明度的白色背景，并自动调整文字、图标和滑动条的对比度颜色。
    *   适配了搜索框、ExpansionTile、屏蔽按钮等所有 UI 细节。
