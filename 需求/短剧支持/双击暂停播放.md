# 播放器双击暂停 / 播放需求

## 背景

短剧播放页的手势交互需要收敛，避免「单击、双击、按钮组显隐」互相干扰，导致操作感发脏、发乱。

当前希望统一为两条最清晰的规则：

- 单击只负责按钮组显隐。
- 双击只负责播放 / 暂停切换。

## 目标

- 支持双击屏幕切换播放状态。
- 按钮组隐藏时，双击暂停或播放后仍保持隐藏。
- 按钮组可见时，双击也不主动改变按钮组显隐状态。
- 不把双击和按钮组显隐耦合在一起。

## 交互规则

| 场景 | 结果 |
|------|------|
| 播放中双击 | 暂停播放 |
| 暂停中双击 | 继续播放 |
| 按钮组隐藏时双击 | 仍保持隐藏，不主动弹出按钮组 |
| 按钮组可见时双击 | 仅切换播放状态，按钮组保持原状态 |
| 单击屏幕 | 仅切换按钮组显隐 |

## 设计原则

1. 手势职责分离。
   单击和双击不要互相接管，避免用户记忆成本上升。

2. 显隐状态独立。
   播放状态变化，不应默认改变按钮组显隐状态。

3. 隐藏优先保持隐藏。
   如果用户当前就是想要干净画面，双击暂停 / 播放后也不要把控制层拉出来。

## 适用范围

- 短剧播放页。
- 复用同一套手势层的播放器控制区域。
- 如果后续横屏播放器也沿用同一交互逻辑，同样遵守这条规则。

## 非目标

- 不修改按钮组布局。
- 不修改主题色。
- 不修改选集、换源、进度条、弹幕等其它交互。
- 不新增双击后的额外提示层。

## 验收标准

- 按钮组隐藏时，双击暂停 / 播放后仍然隐藏。
- 按钮组显示时，双击只切换播放状态，不会强行切换显隐。
- 单击仍然只负责按钮组显隐。
- 双击不会把隐藏状态打破。

## 备注

- 这个需求的核心不是「双击做什么」，而是「双击不要顺手把按钮组也改了」。
- 如果后续要扩展成更多手势，建议继续沿用「单击管显隐，双击管播放」这个边界。
